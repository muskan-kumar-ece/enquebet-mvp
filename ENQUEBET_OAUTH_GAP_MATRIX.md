# ENQUEbet OAuth 2.0 Architectural Gap Matrix

**Project:** ENQUEbet MVP  
**Feature:** Google and GitHub OAuth 2.0 Integration  
**Mode:** READ-ONLY Architectural Audit  
**Date:** October 20, 2026  

This matrix details each functional, architectural, security, and UI requirement for Google and GitHub OAuth 2.0, compares it against the existing codebase implementation, identifies specific gaps, and outlines proposed changes, associated risks, and verification methods.

---

| Requirement | Existing Implementation | Evidence / File Location | Gap | Proposed Change | Risk | Verification Method |
|---|---|---|---|---|---|---|
| **Google Authentication (Sign-in & Sign-up)** | None. Google OAuth is not configured or handled. `google-auth==2.52.0` is present in dependencies but uncalled. | `backend/requirements.txt:63`<br>`backend/apps/users/urls.py` | No endpoint or handler exists to receive Google ID tokens or authorization codes. | Implement `POST /api/v1/auth/oauth/google/` using `google.oauth2.id_token.verify_oauth2_token` with client ID validation, audience check, and clock skew tolerance. | Expired or forged Google tokens if signature verification is incomplete. | Mock expired and invalidly signed ID tokens in `tests_oauth.py`; assert HTTP 400 with descriptive error. |
| **GitHub Authentication (Sign-in & Sign-up)** | None. GitHub OAuth is not integrated. `requests` and `requests-oauthlib` exist in dependencies. | `backend/requirements.txt:140-141`<br>`backend/apps/users/views.py` | No endpoint or server-to-server exchange exists to swap GitHub codes for access tokens. | Implement `POST /api/v1/auth/oauth/github/` using `requests.post('https://github.com/login/oauth/access_token')` with client ID and secret. | GitHub API rate limits or network timeout on external request. | Test with mock GitHub server responses and simulate network timeouts with 5s timeout and structured fallback. |
| **Social Account Identity Storage** | None. Only `User` model exists. No provider mapping table exists. | `backend/apps/users/models.py:9-73`<br>`backend/apps/users/migrations/` | Cannot map Google `sub` or GitHub `id` to a Django `User`. User model would become bloated if fields were directly added. | Create `SocialAccount` model with `provider`, `uid`, `user` foreign key, `provider_email`, `extra_data`, and unique constraints on `(provider, uid)` and `(user, provider)`. | Database table migration failure or schema conflict. | Additive Django migration (`0009_socialaccount.py`). Validate constraint violations in unit tests. |
| **GitHub Private & Unverified Email Extraction** | None. Existing registration requires manual email entry. | `backend/apps/users/views.py:109-130`<br>`backend/apps/users/serializers.py:247` | If GitHub user hides their email on profile, `GET /user` returns `email: null`, which would cause registration failure. | In GitHub OAuth service, call `GET https://api.github.com/user/emails` and filter for `primary == True` and `verified == True`. If no verified email exists, reject. | User without verified GitHub email cannot sign up. | Unit test with mocked GitHub email lists (including unverified, non-primary, and primary verified emails). |
| **Account Linking by Email** | None. Registration rejects duplicate emails with HTTP 400. | `backend/apps/users/serializers.py:259-261` | Existing email/password users who click "Continue with Google" or "Continue with GitHub" would be rejected with duplicate email errors. | Implement safe account linking: If email matches an existing user AND provider confirms `email_verified == True`, automatically link the `SocialAccount` to the existing user. | Account takeover if provider email is unverified or spoofed. | Verify that unverified emails reject with HTTP 400; verify verified emails link cleanly without changing password. |
| **Username Generation & Deduplication** | Serializer rejects duplicate usernames with HTTP 400. | `backend/apps/users/serializers.py:262-265`<br>`backend/apps/users/models.py:13` | OAuth profile usernames may conflict with existing builder usernames (e.g. `john_doe`). | Implement deterministic slug generation with collision deduplication (e.g. `john_doe`, `john_doe_1`, `john_doe_2`). | Potential race condition under concurrent signups with same base name. | Wrap user creation in database transaction with unique retry loop; unit test with simulated collision. |
| **Password Setting for OAuth Users** | `MePasswordView` requires `current_password` and checks `user.check_password()`. | `backend/apps/users/views.py:284-293`<br>`frontend/components/settings/SecuritySection.tsx:48-73` | OAuth users have `unusable_password` (`user.has_usable_password() == False`). They can never pass `current_password` check in settings. | Create `POST /api/v1/users/me/set-password/` for users with `has_usable_password() == False`. Update `SecuritySection` to display "Set Password" button. | Exposing set-password to users who already have a password. | Enforce `if request.user.has_usable_password(): return HTTP 400` in `SetPasswordView`. Unit test both cases. |
| **JWT Generation & Token Rotation** | SimpleJWT is fully functional for standard email/password login. | `backend/apps/users/views.py:120,155`<br>`backend/config/settings.py:288-293` | OAuth endpoints must issue identical SimpleJWT tokens (`RefreshToken.for_user(user)`) to maintain unified session behavior. | Re-use existing `RefreshToken.for_user(user)` in OAuth views, returning identical `{ user, access, refresh }` payload format. | Divergence in token payload structure breaking `ApiClient`. | Validate response schema matches `UserLoginSerializer` output exactly. |
| **Session & Device Tracking** | `record_user_session(request, user, refresh)` tracks IP, browser, OS, and JTI. | `backend/apps/users/views.py:79-106` | OAuth sign-ins might bypass session logging if not explicitly called in the new OAuth views. | Call `record_user_session(request, user, refresh)` in both `GoogleOAuthView` and `GitHubOAuthView`. | Incomplete audit trail in user security settings. | Query `UserSession.objects.filter(user=oauth_user)` in unit tests after OAuth login; verify `is_current=True`. |
| **WebSocket Single-Use Ticket Support** | `WebSocketTicketView` generates ephemeral tickets for authenticated users. | `backend/apps/users/views.py:171-185` | None. Once JWT is acquired via OAuth, `/api/v1/auth/ws-ticket/` works identically because it relies on standard `IsAuthenticated`. | No changes needed to `WebSocketTicketView`. OAuth users will use standard JWT to obtain tickets. | None. | Execute `api.getWsTicket()` with an OAuth-derived access token in integration tests. |
| **OAuth CSRF State Parameter Validation** | No OAuth state validation exists. | `backend/apps/users/views.py` | State parameter tampering or CSRF attacks during GitHub redirect callback. | Frontend generates cryptographically secure random `state` (32 bytes), saves in `sessionStorage`, sends in authorization URL, and validates upon callback. | Expired or mismatched state in multi-tab usage. | Test callback with invalid/tampered state; verify error toast and immediate redirect to `/auth/login`. |
| **Token Delivery Security (No tokens in URLs)** | `ApiClient` reads tokens from response body or `localStorage`. | `frontend/lib/api.ts:57-70`<br>`frontend/lib/contexts/AuthContext.tsx:68-84` | Naive OAuth implementations redirect with `?access=...&refresh=...` in browser address bar. | Use Headless Code/Credential Exchange: Frontend receives code/credential at `/auth/callback`, POSTs payload via API body to backend, receives JWT in JSON response. | Token leakage in browser history, proxy logs, or `Referer` headers. | Verify URL remains `/auth/callback` during exchange and tokens are never written to URL parameters. |
| **Frontend Auth Pages & Mascot Integration** | `/auth/login` and `/auth/register` feature `AuthRobot` with input synchronization. | `frontend/app/auth/login/page.tsx:62-72`<br>`frontend/app/auth/register/page.tsx:81-91` | No social buttons exist on login or registration pages. | Add sleek "Continue with Google" and "Continue with GitHub" buttons separated by cyber divider. Add robot animation triggers for button hover. | Layout shift or breaking the 3D robot's focus/typing listeners. | Visual inspection on desktop and mobile viewports; verify mascot continues reacting to typing and password peek. |
| **Frontend OAuth Callback Route** | No `/auth/callback` page exists. | `frontend/app/auth/` | GitHub redirect target does not exist, causing 404 Not Found upon returning from provider. | Build `frontend/app/auth/callback/page.tsx` with animated cyber loading state, error display, and automated token handshake. | Infinite loading spinner if network fails during code exchange. | Test with simulated API network failures; verify user-friendly error message and fallback button. |
| **Global Auth Context State** | `AuthContext` only supports `login(email, password)` and `register(data)`. | `frontend/lib/contexts/AuthContext.tsx:47-56` | No helper exists to ingest tokens and profile from an external OAuth exchange without re-authenticating. | Add `setAuthSession(response: { user: any; access: string; refresh: string }): void` to `AuthContextType` and `AuthProvider`. | Stale user state if `localStorage` and React state fall out of sync. | Verify `user`, `isAdmin`, and `isStaff` are updated immediately upon calling `setAuthSession()`. |
| **Connected Accounts Management in Settings** | Security section only supports password change and active sessions. | `frontend/components/settings/SecuritySection.tsx:111-200` | Builders cannot view which social providers are connected to their account, or link/unlink them. | Add "Connected Builder Accounts" card in `SecuritySection.tsx` showing Google and GitHub connection statuses and action buttons. | Disconnecting only auth method leaving user locked out. | Prevent unlinking provider if user has no usable password and no other connected social account. |
| **Environment Variable Conventions** | Backend and frontend templates contain database, Redis, and Cloudinary keys. | `backend/.env.example:1-75`<br>`frontend/.env.example:1-30` | Missing Google and GitHub client IDs, secrets, and redirect URIs. | Add `GOOGLE_OAUTH_CLIENT_ID`, `GOOGLE_OAUTH_CLIENT_SECRET`, `GITHUB_OAUTH_CLIENT_ID`, `GITHUB_OAUTH_CLIENT_SECRET`, and `NEXT_PUBLIC_*` equivalents to `.env.example` files. | Developer setup confusion or missing secrets in production Render dashboard. | Test backend startup with missing OAuth variables; ensure graceful degradation (log warning, don't crash). |
| **Mock Authentication Prevention** | No mock auth exists in repository. | Entire repository search | Risk of developers adding hardcoded dummy tokens or testing bypasses that leak into production. | Strictly forbid mock auth endpoints in production. Use isolated Python unit test mocks (`unittest.mock.patch`) exclusively. | Bypass of real auth logic in production if debug toggles fail. | Run security audit verifying zero conditional bypasses based on request headers or unverified parameters. |
